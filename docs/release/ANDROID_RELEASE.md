### 0.2 How to get the APK / AAB (workflow `.github/workflows/app-android.yml`, "App — Android (APK + AAB)")

* **Trigger:** Actions → "App — Android (APK + AAB)" → *Run workflow* (inputs `version_name`, `version_code`), **or** push to an `arena/**` branch with `[build-app]` in the commit message (the agent sandbox has no JDK/Android SDK and cannot dispatch workflows). Never runs automatically otherwise; never uploads to Play.
* **Steps:** `npm ci` (apps/mobile) → `tsc --noEmit` + app suites + brand-artwork check → **build security gate** (`node scripts/check-build-security.cjs`, blocking: the live `npm audit` must match `security/reviewed-advisories.json`, channel `internal-ci`) → `npx expo prebuild --platform android --no-install --clean` (+ versionCode/permission assertions) → keystore from secrets (only if present) → `node scripts/configure-android-signing.cjs` → `./gradlew :app:assembleRelease :app:bundleRelease` → `apksigner verify --print-certs` / `jarsigner -verify` → artifacts.
* **Artifacts (30 days):** `monte-wo-android-apk-<version>-<code>` (`monte-wo-<version>-<code>-<sha>.apk` + `build-info.json`) and `monte-wo-android-aab-<version>-<code>` (`.aab` + `build-info.json`). `build-info.json` states the signer and `playUploadable: true|false`.
* **Install the APK on a phone:** open the workflow run on GitHub (signed in), download the APK artifact (a zip), unzip it with the Files app, tap the `.apk`, allow "install unknown apps" for that app once. From a computer: `adb install -r monte-wo-<version>-<code>-<sha>.apk`. An APK signed with the debug keystore cannot be updated in place by a Play-signed build — uninstall first.
* **Publish job (opt-in, 2026-11-04):** when the commit message also contains `[publish-apk]` (or the dispatch input `publish_release` is set), a second job (`contents: write` on that job only) downloads the APK artifact of the same run and creates a GitHub **pre-release** `app-android-v<version>-<versionCode>` (tag at the built commit; existing tag with the same name is replaced) with the `.apk`, `build-info.json` and `SHA256SUMS.txt`, and notes that state: test build, not Google Play, signer (debug keystore unless the secrets exist), SHA-256, size, minSdk 24, install + uninstall-first instructions, DRAFT standards. The `.aab` is **never** published publicly (artifact only). Direct link pattern: `https://github.com/vitaflexl4-ai/monte-wo/releases/download/app-android-v<version>-<code>/monte-wo-<version>-<code>-<sha7>.apk`.

### 0.3 Signing — what the artifacts are, honestly

| Repository secrets present? | Release build type signed with | Result |
|---|---|---|
| none | Expo's public **debug keystore** (`CN=Android Debug`) | installable test build, **not uploadable to Google Play**; the job prints a warning and labels the artifact |
| all four — `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD` | the owner's **upload keystore** (read from the environment at Gradle time; nothing is written into the repository or the generated project) | `.aab` uploadable to Play **if** that keystore is the upload key registered for the app (Play App Signing); `.apk` suitable for direct distribution with that identity |
| some but not all | — | the job fails (`configure-android-signing.cjs`) rather than producing a mislabelled build |

Create the upload keystore once, outside the repository (`keytool -genkeypair -v -keystore upload-keystore.jks -alias upload -keyalg RSA -keysize 4096 -validity 10000`), back it up in the owner's credential manager, then add the four secrets (`base64 -w0 upload-keystore.jks` for the first). The same secret names are used by the Capacitor workflow (§4), so one set serves both. If the owner's existing EAS credentials should remain the app's identity instead, download that keystore from EAS (`npx eas-cli credentials --platform android`) and use it here — never generate a second identity casually (`docs/mobile/BUILD-AND-SIGN.md`, key continuity).

## 3. Signed release bundle (.aab)

1. Create the **upload keystore once**, outside the repository (e.g. a password manager + offline backup):
   ```sh
   keytool -genkeypair -v -keystore upload-keystore.jks -alias upload -keyalg RSA -keysize 4096 -validity 10000
   ```
   Enrol the app in **Play App Signing** (default for new apps): Google holds the app signing key, you keep the upload key. Losing the upload key is recoverable via Play support; losing a self-managed signing key is not.
2. Export the signing environment (never commit it; `*.jks`, `*.keystore`, `.env` are git-ignored):
   ```sh
   export ANDROID_KEYSTORE_PATH=/secure/path/upload-keystore.jks
   export ANDROID_KEYSTORE_PASSWORD='…' ANDROID_KEY_ALIAS=upload ANDROID_KEY_PASSWORD='…'
   export MONTE_WO_VERSION_NAME=0.1.0 MONTE_WO_VERSION_CODE=1
   ```
3. Build:
   ```sh
   cd android && ./gradlew --no-daemon bundleRelease
   # → app/build/outputs/bundle/release/app-release.aab
   jarsigner -verify app/build/outputs/bundle/release/app-release.aab   # "jar verified"
   ```
   Without the four `ANDROID_KEY*` variables Gradle produces an **unsigned** bundle (Play rejects it) — intentional so that no credential is ever needed in Git.
4. Upload manually in Play Console → Testing (Internal testing first) → create release → upload `.aab` → release notes (include the Git commit SHA).
