# MONTE WO — App Foundation Step 1 Completion Report

**Scope executed:** Step 1 only — a responsive dashboard foundation / app shell inside the existing `vitaflexl4-ai/monte-wo` repository. No Step 2 work (accounts, performance records, ranking logic, nutrition data, camera, backend) was started.

**Repository:** `vitaflexl4-ai/monte-wo` · **Branch:** `arena/7a19420f-monte-wo` (branched from `main` at `b6c66da`) · **Not deployed.** No DNS, production settings, databases, media uploads, migrations or external integrations were touched. `flex-ai-db` and `monte-wo-waitlist` were not touched.

## Result

A new route **`/dashboard/`** is the MONTE WO **app shell** — not a web page: it has its own chrome (sidebar on desktop, native-style bottom tab bar on phones/tablets), no marketing hero, no website footer or header, an app manifest so it installs as a standalone app, and it stays out of the public site's route list, navigation, sitemap and search index. It renders the approved mockup direction (premium dark mode, glassmorphic panels, blue + red accents, strong typography) with the existing MONTE WO logo, colour tokens, fonts and status-badge conventions. It is generated by `scripts/build_dashboard.py` from `content/dashboard/en.json` and the real draft sources already in the repo (`content/strength/disciplines.json`, the four `*-standard-draft-1.json` rulebooks, `public/ranks.json`, `content/exercises.json`). Everything runs on local UI state: no backend, no fetch, no storage, no cookies, no camera permission, no new runtime or dependency.

Every panel tells the truth: **DRAFT — NOT OFFICIAL**, **NOT CONNECTED**, **DEMO**, **PLACEHOLDER · NOT IMPLEMENTED IN STEP 1**. No athlete, rank, verified achievement, ranking position, nutrition value or integration is shown as real. No rank is transferred between disciplines and no overall rank exists.

## Features implemented

### App shell
- Compact app header on every screen: `OVERVIEW / Dashboard` title, one-line state note and a **status strip** (Account · NOT CONNECTED, Standards · DRAFT — NOT OFFICIAL, Nutrition source · NOT CONNECTED, Camera · NOT CONNECTED). No marketing headline or intro copy.
- Sticky sidebar at ≥1024px (emblem + `MONTE WO` wordmark, "FOUNDATION · STEP 1", nine navigation items with icons, "Athlete · Not signed in" chip, a single "About MONTE WO" link); top bar with an `APP / {view}` crumb and the account chip. The brand mark returns to the Dashboard view, not to the website.
- Below 1024px a fixed **bottom tab bar** (Dashboard, Performance, Rankings, Nutrition, More) with active indicator and safe-area padding replaces the sidebar; **More** opens the full nine-item navigation as an off-canvas drawer (`aria-expanded`/`aria-controls`, backdrop, Escape closes, focus moves into the navigation and returns to More, closed drawer is `visibility:hidden`, state resets when resized back to desktop). Content padding clears the bar.
- Installable: `/dashboard/manifest.webmanifest` (`start_url`/`scope` `/dashboard/`, `display: standalone`, brand icons), `apple-mobile-web-app-*` meta, `apple-touch-icon`, `viewport-fit=cover`. The public site keeps its own `/manifest.json` untouched.
- No website footer; Privacy, Terms, Methodology, account deletion and About live under **Settings**.
- Navigation items (exact order): Dashboard, My Profile, Performance, Standards, Rankings, Exercise Library, Nutrition, Verification, Settings. Views are hash routes (`#dashboard` … `#settings`) inside one page: `aria-current="page"`, document title `"{View} | MONTE WO App Foundation"`, focus moves to the view heading, unknown hashes fall back to the dashboard, browser back/forward works, and a CSS `:target` fallback keeps every view reachable without JavaScript.
- Eight destinations are honest placeholders with one uniform header badge **PLACEHOLDER · NOT IMPLEMENTED IN STEP 1**, a "Planned for the MVP" list where applicable and "Works today on the public site" links to real pages (methodology, exercise standards, rank identities, free tools, privacy, account deletion). Standards lists the four draft rulebooks (variation, equipment, number of validity checks) read from the real JSON; Rankings shows the nine rank identities (Debitan → Lejand) from `public/ranks.json` with "no threshold tables are approved … no athlete holds a rank"; Exercise Library lists the seven existing guide groups.
- Page is `noindex, nofollow`, excluded from the public route list, header navigation and sitemap; the offline service worker precaches the shell (`DASHBOARD_ASSETS`, core cache bumped to v12).

### Dashboard view
- Four independent **Discipline Rank** cards (Squat, Bench Press, Deadlift, Biceps Curl) — "No official rank", MONTE Standard: DRAFT, Athlete data: NOT CONNECTED, link to each discipline's methodology section. Footnote: no rank transfers between disciplines, no overall rank.
- **Panel 01 — Muscle Character View:** centred dark-mode SVG silhouette with four interactive regions (Chest, Core, Arms, Legs) as keyboard-operable `role="button"`/`aria-pressed` groups plus matching chips. Hover shows `Region · NOT CONNECTED` in the live preview line; click/Enter/Space selects (click again deselects) and fills the detail card with the region's status badge, description, launch disciplines (Chest → Bench Press, Arms → Biceps Curl, Legs → Squat · Deadlift, Core → "None — supports all four disciplines") and a link to the existing written guides. No fictional ranks or data appear anywhere in the panel.
- **Panel 02 — Food Scan & Macro Logger (DEMO · NOT CONNECTED):** food search input over four labelled demo items, quick-filter pills Griot / Diri ak Djon Djon / Chicken Breast / Oatmeal (toggle, sync with the search field), demo results with "Nutrition values unavailable", an in-memory "Today's demo log" with add/remove and item count, Protein/Carbs/Fats trackers that stay `— g · NOT CONNECTED`, and a **Scan Food via Camera** button that opens a `<dialog>` viewfinder mockup ("NO LIVE FEED", "DEMO · NO CAMERA ACCESS") with an explicit statement that it does not request camera permission, capture images or recognise food. The site's `Permissions-Policy: camera=()` header remains unchanged.

### Responsive behaviour
Breakpoints at 1280 / 1024 (tab bar + drawer) / 760 / 480 px plus a container query that stacks the muscle panel when it is narrow. Verified without horizontal overflow at 1440, 1280, 1024, 1023, 900, 768, 640, 480, 390 and 320 px for the dashboard, rankings, standards and library views. `prefers-reduced-motion` disables transitions.

## Remaining limitations (by design in Step 1)

- No accounts, authentication, athlete data, performance records, verification workflow or ranking computation. Discipline cards cannot show a rank until standards are approved and performances exist.
- The muscle view does not reflect any athlete; its status is always NOT CONNECTED. Region shapes are an original stylised silhouette, not medical anatomy.
- The food logger searches four hard-coded demo items only; nothing is saved between reloads; macro totals are intentionally empty; the camera mockup cannot scan or access a camera (and the site header disables the camera for all pages).
- No translations (English copy only in `content/dashboard/en.json`; the public site's language switcher does not cover the shell yet).
- The pre-existing `INTER-LICENSE.txt` baseline mismatch in `npm test` remains open for the maintainers (asset is protected; not altered here).
- The app shell lives at `/dashboard/` inside the repository that also serves the public website; whether the app should become the root `/` experience (or its own deployment) is an open product decision, see below.
- Visual/behaviour verification used Chromium only; Safari/Firefox and real devices were not tested.
